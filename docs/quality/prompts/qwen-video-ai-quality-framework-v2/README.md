# 视频 AI 质检提示词：通用模板 + 场景要求拼接（V2）

规则版本：`video_qc_v2` ｜ 提示词版本：`qwen_video_qc_prompt_v4`（见 `manifest.json`）

最后更新：2026-08-30

## 1. 提示词的拼接结构

完整质检提示词由三部分组成（服务端 `evaluationSystemPrompt` 拼接，见
`backend/src/ai-quality/evaluation-context.ts`）：

```text
完整提示词 = ① 通用模板（本目录 system.txt，服务端锁定版本）
           + ② 平台运行时规则快照（质量规则 + 标签字典，服务端锁定）
           + ③ 任务要求区块（提交时锁定的场景描述 / 分条要求 / 质检提示词内容）
```

- ① 是**通用模板**：五维评分规则、硬性否决、D1~D5 判定标准、有效时长计算与输出
  结构，与具体任务无关，所有视频共用同一份。
- ② 由服务端按当前生效的质量规则与标签字典快照生成，保证同一任务内判定基准一致。
- ③ 是**场景要求拼接内容**：每个任务在「AI 要求规范化」确认后，把
  `scene_description`（场景描述）、`requirements`（hard/soft 分条要求）、
  `quality_notes`（质检提示词内容）锁进提交快照；AI 质检按
  【6.1 D4 = 任务符合度】逐条判定，输出 `task_compliance`，服务端再按条目复算 D4。

### 1.1 任务要求区块的渲染格式（服务端权威）

```json
{
  "scene_name": "家庭-厨房",
  "scene_description": "……（场景边界描述，见第 3 节）",
  "requirements": [
    { "type": "hard", "content": "必须使用第一人称视角拍摄……" },
    { "type": "soft", "content": "画面清晰、光线充足……" }
  ],
  "quality_notes": ["……（场景特有质检关注点，见第 3 节）"]
}
```

## 2. 任务类型体系与预设场景

任务分为三类（`collection_tasks.task_type`，见 `backend/src/tasks/preset-scenes.ts`）：

| 类型 | 说明 | 场景要求区块 |
| --- | --- | --- |
| `generic` 通用任务 | 不绑定具体场景的综合任务，创建页最显眼入口 | 使用「通用任务」拼接内容，D4 重点为任务真实性/完整度/有效价值，不校验特定场景 |
| `preset` 预设场景 | 从预设目录选择，自动带出模板（描述/要求/提示词） | 使用对应场景的拼接内容 |
| `custom` 自定义 | 管理员手工填写场景与要求 | 使用管理员填写的内容（经 AI 规范化后锁定） |

预设场景共 5 个：家庭-厨房 / 家庭-客厅 / 家庭-卧室 / 办公室 / 工厂。
以下拼接内容与 `backend/src/tasks/preset-scenes.ts` 保持一致（代码为唯一权威来源，
本文件用于评审与离线查阅）。

## 3. 各预设场景的拼接内容

### 3.1 家庭-厨房

场景描述（scene_description 基础稿）：
> 家庭厨房环境中的真实做饭/备餐操作。应出现灶台、水槽、操作台、炊具、餐具与食材；
> 操作类型包括备餐切配、炒菜烹饪、煲汤蒸煮、清洗碗筷、收纳整理、使用小家电等。
> 不应出现卧室、客厅或非厨房商业后厨画面；虚拟合成或纯摆设画面判定不匹配。

分条要求（requirements，供 AI 规范化拆分 hard/soft）：
1. 必须使用第一人称视角拍摄，画面自然向前或略向下，双手与刀具、食材、锅具等操作对象全程可见。
2. 操作必须真实完整：从备料、处理、烹饪到成品完成的全过程连续记录，不得剪辑拼接。
3. 必须完成至少一个可核验的厨房任务结果（如做出一道菜、洗净一批餐具、整理好橱柜）。
4. 明火与刀具操作必须全程在画面内可见，出现热油、蒸汽等必要等待画面时不得判为无效。
5. 不得出现人脸、手机屏幕、灶台边票据、带地址的包装等隐私信息。
6. 画面清晰、光线充足，灶台背光时需注意曝光，避免长时间过曝或欠曝。

质检提示词内容（quality_notes）：
- 场景边界：家庭厨房——应出现灶台/水槽/操作台、炊具、餐具、食材等；卧室、客厅或非厨房商业后厨画面判定场景不匹配。
- 厨房特有质检关注点：明火烹饪时必须确认火源与锅具操作真实可见；蒸煮焖等必要等待属于有效时长，不得标记为无效。
- 刀切、颠勺等关键动作的手部细节应清晰可辨，模糊或裁切导致无法确认操作真实性时需触发人工复核。

### 3.2 家庭-客厅

场景描述（scene_description 基础稿）：
> 家庭客厅环境中的真实整理/清洁/家电操作。应出现沙发、茶几、电视柜、电视墙等客厅特征；
> 操作类型包括整理收纳、桌面擦拭、地面清洁、收纳归位、窗帘拉合、家电操作等。
> 不应出现卧室床品、厨房灶台等画面；仅展示静止陈设或无实质操作判定为无效任务。

分条要求（requirements）：
1. 必须使用第一人称视角拍摄，双手与抹布、拖把、收纳箱等操作对象全程可见。
2. 操作必须真实完整：整理/清洁前后状态对比清晰，结果可核验，不得循环重复同一动作。
3. 操作对象（沙发、茶几、地面、家电等）与作用位置必须在画面内可见，不得长期只拍手部特写。
4. 不得出现人脸、手机屏幕、电视播放中的敏感画面、门牌号等隐私信息。
5. 画面稳定清晰，擦拭与拖地等动作轨迹自然，避免剧烈晃动导致无法辨认。

质检提示词内容（quality_notes）：
- 场景边界：家庭客厅——应出现沙发/茶几/电视柜/电视墙等客厅特征；卧室床品、厨房灶台等画面判定场景不匹配。
- 客厅特有质检关注点：清洁类任务需确认污渍/杂乱状态的变化真实可见；整理收纳需确认物品归位前后差异清晰。
- 扫地机器人等自动化设备运行时，若画面长时间无人操作且无有效任务信息，可标记为无效片段。

### 3.3 家庭-卧室

场景描述（scene_description 基础稿）：
> 家庭卧室环境中的真实整理/清洁操作。应出现床、床品、衣柜、梳妆台等卧室特征；
> 操作类型包括铺床叠被、更换床品、衣物折叠收纳、衣柜整理、卧室地面清洁等。
> 不应出现客厅沙发区、厨房等画面；仅展示静止的床铺与衣柜判定为无效任务。

分条要求（requirements）：
1. 必须使用第一人称视角拍摄，双手与床品、衣物、收纳盒等操作对象全程可见。
2. 铺床、叠被、折叠衣物等操作必须真实完整，动作连贯，不得剪辑或循环。
3. 操作结果必须可核验：展示铺好的床铺、叠好的衣物或整理后的收纳空间。
4. 不得出现人脸、手机屏幕、床头票据、门牌号等隐私信息。
5. 床铺与衣物整理时注意光线，避免窗帘逆光导致操作对象看不清。

质检提示词内容（quality_notes）：
- 场景边界：家庭卧室——应出现床/床品/衣柜/梳妆台等卧室特征；客厅沙发区、厨房等画面判定场景不匹配。
- 卧室特有质检关注点：铺床叠被类任务需确认床品形态变化真实（如褶皱消失、被芯套入）；衣物折叠需确认折叠动作与结果可见。
- 操作对象被身体、枕头或床单遮挡导致关键动作不可辨认时，只扣 D2，不得误判任务未执行。

### 3.4 办公室

场景描述（scene_description 基础稿）：
> 办公室环境中的真实整理/文档/设备操作。应出现办公桌、工位、文件柜、办公设备等办公特征；
> 操作类型包括工位整理、文件归档装订、文具耗材收纳、打印机/碎纸机/投影仪等设备操作、会议桌椅布置等。
> 不应出现家庭卧室、车间工位等画面；涉及文字内容时不得清晰拍摄敏感信息。

分条要求（requirements）：
1. 必须使用第一人称视角拍摄，双手与文件、装订机、收纳盒等操作对象全程可见。
2. 操作必须真实完整：文件分类、装订、归档、上架等过程连续，结果可核验。
3. 涉及文字内容时，不得出现可识别的人脸、姓名、电话、地址、合同金额等敏感信息，必要时遮挡后再拍摄。
4. 办公设备（打印机、碎纸机等）操作时需确认设备状态与操作结果可见。
5. 画面清晰稳定，文件上的文字在关键步骤中应清晰可辨（分辨率不足时提前调整拍摄距离）。

质检提示词内容（quality_notes）：
- 场景边界：办公室——应出现办公桌/工位/文件柜/办公设备等办公特征；家庭卧室、车间工位等画面判定场景不匹配。
- 办公特有质检关注点：文件归档需确认分类与装订动作真实、归档前后位置变化可见；文字敏感内容被清晰拍摄到属于隐私问题。
- 桌面整理类任务需确认物品移动与归位过程可见，仅展示静态工位判定为无效任务。

### 3.5 工厂

场景描述（scene_description 基础稿）：
> 工厂车间/工坊环境中的真实产线操作。应出现工位、产线、机床、工具、工件等车间特征；
> 操作类型包括零配件装配、工具使用、产品检测分拣、包装打包、物料搬运上架、设备点检维护等。
> 不应出现家庭场景或办公室画面；内容仍须为真实具身操作，遵守车间安全规范。

分条要求（requirements）：
1. 必须使用第一人称视角拍摄，双手与工件、工具、包装材料等操作对象全程可见。
2. 操作必须真实完整：从取料、加工/装配、检测到成品/包装完成的全过程连续记录，不得剪辑拼接。
3. 工具与工件的接触、装配位置、检测结果等关键环节必须清晰可辨。
4. 不得出现人脸、工牌、设备铭牌上的敏感信息、涉密图纸与文件。
5. 遵守车间安全规范：明火、高速运转设备等危险画面需保持安全距离拍摄，内容仍须真实。
6. 画面清晰，车间光线不足时需补充光源，避免长时间欠曝导致操作不可辨认。

质检提示词内容（quality_notes）：
- 场景边界：工厂车间——应出现工位/产线/机床/工具/工件等车间特征；家庭场景或办公室画面判定场景不匹配。
- 工厂特有质检关注点：装配与检测类任务需确认工件状态变化（如装配前后、检测结果）真实可见；工具与工件接触细节模糊时需人工复核。
- 设备运行等待、烘干固化等必要等待属于有效时长；长时间无有效任务信息的空转画面可标记为无效。

## 4. 通用任务的拼接内容

通用任务不绑定具体场景，场景固定为「通用」（发布时不写入标签字典）：

场景描述基础稿：
> 真实具身操作环境，不限具体场景（家庭、办公室、店铺、车间等均可）。
> 内容必须是真实物体操作：有明确目标、推进过程与可核验的结果。

分条要求（requirements）：
1. 必须使用第一人称视角拍摄，画面保持自然向前，不得出现他人代拍、固定支架远景或大量第三人称画面。
2. 双手与主要操作对象全程保持画面内可见，操作过程不得长期移出画面。
3. 操作必须真实完整：有明确目标、推进过程与可核验的结果，不得摆拍、循环重复或拼接凑时长。
4. 全程不得出现人脸、手机屏幕、门牌号、地址单、登录页面等隐私与敏感信息。
5. 画面清晰、曝光正常、无明显抖动与频繁冻结，分辨率不低于 720P。
6. 场景与内容应为真实具身操作环境，不得使用纯绿幕、虚拟合成或仿真演示画面。

质检提示词内容（quality_notes）：
- 本任务不限定场景：scene_match 仅校验内容是否为真实具身操作，不再要求匹配特定场景；场景明显为虚拟合成或纯摆设时判定不匹配。
- 通用任务的 D4 判定重点为任务真实性、完整度与有效价值：L0 空转、重复循环、无结果展示的内容应大幅扣分。

## 5. 修改指引

- 预设场景的模板内容（描述/要求/提示词）以 `backend/src/tasks/preset-scenes.ts` 为唯一权威来源；
  本文件用于评审与离线查阅，修改时请同步更新两处（或直接以代码为准）。
- 通用模板（五维评分等）修改必须新建提示词版本并更新 `manifest.json`，禁止原地覆盖已上线版本。
