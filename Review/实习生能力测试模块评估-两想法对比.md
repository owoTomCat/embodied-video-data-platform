# 实习生能力测试模块评估：想法一 vs 想法二

> 评估日期：2026-08
> 评估对象：具有 VLA 微调（OpenPI π0.5 / LIBERO-10）与 RDT-1B 小样本双臂操作经验、擅长数据构建与受控评测的实习生
> 时限假设：2~3 天

## 结论先行

| | 想法1：手关节标注模块 | 想法2：ego 数据价值 AI 标注体系 |
|---|---|---|
| 2-3 天可行性 | ✅ 能（1.5~2.5 天，风险低-中） | ✅ 能（2.5~3 天，需范围界定） |
| 系统增益 | 🟡 中等（产品扩展 + 质检增强） | 🟢 高（补上规划中缺失的"数据价值"层） |
| 对实习生适配度 | ⚠️ 偏机械，测不出研究能力 | ✅ 高度匹配，能体现真实能力 |
| 主要风险 | ego 视角关键点丢失、验证无真值 | 体系变成不可证伪的空泛标准 |

**建议：以想法2为主体 + 内嵌轻量手部信号组件（MediaPipe 关节覆盖率）作为规则信号，与 LLM 语义打分构成"初检 + 规则复算"混合体系。**

## 平台现状与落点

- 现状链路：上传 → 媒体解析 → Qwen3.7 五维 AI 质检（第 2 维即"手部和操作对象可见性"，但为 LLM 定性判断）→ 人工复核 → 积分 → 交付包。
- 总体方案已明确"质量、内容标签和数据价值分别建模"（具身智能数据外包平台-总体方案与待确认事项.md L106），但一期"数据价值"只实现了库存覆盖度/稀缺度（L3），没有"对具身模型训练有效性"维度。
- 现有标注层（L2）仅粗标签：第一视角、场景、对象工具、动作片段、动作完整性。
- 落点：想法1 = 给内容标签加细粒度能力；想法2 = 补上"数据价值"层中最值钱的部分。

## 想法1：视频手关节标注模块

### 可行性（2-3 天 OK，无需外部 API）

- 2D：MediaPipe Hands（21 关键点/手，实时、免费、VIDEO 跟踪模式）；ATHENA 工具箱可参考。
- 3D：HaMeR（3D MANO 网格 + 关节，训练含 Ego4D，遮挡鲁棒，需 GPU）。
- 端到端参考：Open-AoE（蚂蚁开源 ego 操作数据集 + 自动标注工具链，中文文档）；egosmith / EgoSteer 管线；EgoHOS（手物分割）。
- 人工校正：CVAT / Label Studio + MediaPipe 骨架自动预标注。
- 工作量：D1 格式统一 + MediaPipe 基线；D2 HaMeR（可选）+ 输出 schema + 模块封装；D3 抽样验证 + 失败模式报告。
- 风险：ego 遮挡/运动模糊丢点；无真值需抽样人工比对；ego 视角左右手翻转需定义清楚。

### 系统增益：中等

- ✅ 新增可交付资产类型（关节标注 ego 数据）；✅ 质检第 2 维升级为关节覆盖率的硬信号，可进规则复算。
- ⚠️ 不触及核心闭环；对多数 VLA 管线属加分信号而非必需，增益取决于下游客户需求。

### 适配度：偏简单

主要测工程纪律（接口、鲁棒性、文档），测不出判断力与研究能力，对该实习生属"大材小用"。

## 想法2：ego 数据 AI 标注体系 + 91 视频分析

### 难度校准

- **不会太简单**：难点在标准设计——"什么 ego 数据对具身训练有效"无标准答案，需文献 + 训练经验 + 诚实的不确定性处理。
- **不会太难（范围界定后）**：2-3 天交付的是"有方法、有证据、有局限声明的评估体系"而非因果结论。该实习生有"离线 loss 与闭环成功率脱钩"、"PFVC 差异未达显著不归因"的记录，具备必要的诚实素养。
- **能快速上手**：ego 数据与机器人数据经验相邻；文献读一天足够；可复用平台百炼 Qwen3.7 视频理解链路（初检 + 复核 + 规则复算模式）。
- **能体现能力**：文献综述 + 标准设计 + 提示词工程 + 链路工程 + 批量分析 + 诚实汇报，全链路展示。

### 系统增益：高（战略对齐）

1. 分级定价与优先交付（训练价值分进入质检/资产）；
2. 采集指南升级（告诉数采"拍什么才值钱"）；
3. 架构现成可接入（提示词版本化、规则快照、Worker、审计均为现成模式）；
4. 差异化竞争力：从"收视频"升级为"筛出对训练有用的数据"。

### 防糊弄验收标准（写入任务书）

1. 标注 Schema 为 JSON（字段/枚举/权重/阈值明确，含"训练价值分"公式）；
2. 提示词集 ≥5 条（系统 + few-shot），版本化，≥5 个视频实测输出记录；
3. 链路跑通 91 个视频：每视频 JSON + 汇总 CSV，附耗时/成本；
4. 分析报告含证据时间戳、分布、最好/最差样例与明确局限声明（LLM 标注 ≠ 训练增益）。

## 建议

- 目的为"稳妥交付模块" → 想法1；目的为"测试能力上限" → 想法2（推荐）。
- 组合方案：想法2 主体 + MediaPipe 手部信号组件（关节覆盖率作为"手物交互强度"规则信号），复刻"LLM 初检 + 规则复算"混合架构，同时部分验证想法1 的手部能力。
- 节奏：D1 文献 + 体系草案；D2 提示词 + 链路跑通 91 视频（硬性节点）；D3 分析报告 + 局限声明。
